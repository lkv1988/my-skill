# 功能验证

[English](functional-verification.md)

## 优先验证真实用户流程，避免沉迷单元测试覆盖率

不要沉迷于单元测试的高覆盖度，而忽略用户视角的端到端功能验证。在成本可控的情况下，尽可能充分地对用户功能进行端到端测试。证明功能对用户真实可用，比达到 100% 的单元测试覆盖度更有价值。

## 验证结论应来自实际观察结果

说明实际执行了什么、观察到了什么，以及这些证据覆盖的范围。不能把局部测试、Mock 行为或静态检查当作真实用户流程端到端可用的证据。

- **正例：** 在目标环境实际完成“创建 → 保存 → 重新打开”，确认保存的内容仍然存在，并说明环境、操作与观察结果。
- **反例：** 仅 Mock 保存接口返回成功，或只观察到 HTTP 200，就宣称创建、保存和持久化功能全部正常。
